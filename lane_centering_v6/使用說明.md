# v6 車道置中配套程式

兩邊都要換：`jetson_centering.py` 與 `esp32_centering/esp32_centering.ino`。不要混用v3/v4/v5或舊ESP32版本；新版本會做握手確認，舊韌體無法啟動AUTO。

## 安裝順序

1. Ctrl+C停止舊Jetson程式。
2. Arduino IDE開啟完整 `esp32_centering.ino`，選DOIT ESP32 DEVKIT V1與原本的COM埠後上傳；上傳後關閉序列監控，避免佔用串口。
3. 將 `jetson_centering.py` 放到Jetson，沿用原本OpenCV、NumPy、Flask、pyserial環境。
4. 執行：

   ```bash
   python3 jetson_centering.py --port /dev/ttyUSB0
   ```

   若是 `/dev/ttyACM0` 就更換路徑。瀏覽器仍開Jetson IP的5000埠。

5. 等網頁顯示ESP32連線，先使用MANUAL架空確認前進、後退、左右转與STOP；確認兩輪前進方向正確後才放地低速測試AUTO。原先左輪只能後退的原因若仍存在，單靠新控制器無法確保回線。

## 置中控制

Jetson偵測兩側線並生成綠色前方中心路徑，在兩線共同可見的高度選目標點。OFFSET定義為「車道中心－鏡頭中心」：正值表示應右轉，負值表示應左轉。

這版直接依OFFSET決定補償上限，使用平滑曲線：

```text
u = clamp((abs(OFFSET)-5)/(45-5), 0, 1)
強度上限 = u² × (3-2u)
內側輪比例 = 1 - 0.05 × 補償強度
```

| OFFSET絕對值（320×240影像像素） | 穩定偏移時內側輪比例 |
|---:|---:|
| 0～5 | 100%：取消轉向降速 |
| 15 | 約99.22% |
| 25 | 97.5% |
| 45以上 | 95% |

強度增加時緩升，接近目標時下降立即受距離上限約束。OFFSET變化率用來在快速靠近中心時提前減少補償，不能讓修正方向在仍未越過中心時反轉；因此不是舊版僅依PD steering大小決定比例。表格是穩定偏移、Kick結束、尚未加入RPM修正時的比例。

Jetson傳送 `DRIVE,speed,turn`，turn為-1～1：正值左轉、負值右轉。中心死區內turn=0；速度先從0.12起步，保持至少1秒且連續穩定0.8秒後，每秒增加0.03，最高0.24。偏移變大時回低速。相機讀取、抓線與JPEG編碼分開，保留最新影格，不累積待處理影片。

## ESP32 PWM與編碼器回授

保留原腳位、143／147 A相RISING脈衝設定。採用你確認的69:72左右比例，按先前要求放大：

| 設定 | 左輪PWM | 右輪PWM |
|---|---:|---:|
| 低速0.12 | 154 | 166 |
| 高速0.30（手動） | 168 | 180 |
| 150ms起步Kick | 168 | 180 |

依你回報手動前進往右偏，左輪先降低約2%，本次再各降低2格PWM；這組取代先前左156／170設定。RPM回授仍會在穩定後修正輪速差。

最高AUTO命令0.24介於上述兩組，轉向時內側輪比例逐漸95%～100%，PWM增減仍有緩升降，STOP直接輸出0。PWM上限200。

依你最新要求，轉向與RPM回授相加後，每輪目標PWM限制在該輪當下直行基準的±5%與±9格之內，取較小者，確保補償差值不到10格。使用向內取整的上下限避免整數PWM超出限制。例如低速左基準154，補償目標範圍147～161；右基準166，範圍158～174。起步Kick、速度切換時的PWM緩升降、STOP及手動單輪轉彎是獨立行為，不屬於這個穩態補償幅度。

編碼器每200ms更新RPM，經濾波後，ESP32會用有限幅的P/I差速修正維持要求的左右RPM比例：直行時希望左右RPM相同，轉彎時希望內側RPM按要求降低。修正以目前69:72的PWM為前饋，每輪額外修正最多8格；不使用未量測的絕對目標RPM或m/s。

因此開啟RPM回授後，外側輪PWM也可能為了維持輪速稍微變動，並非固定不變。沒有有效雙側編碼器脈衝時不更新回授，不能宣稱兩輪實际RPM已相同。若兩輪直徑不同，即使RPM相同，地面速度仍不相同。

參數在ESP32開頭：`ENABLE_RPM_SYNC=true`、`SYNC_KP=0.03`、`SYNC_KI=0.025`、`MAX_SYNC_TRIM=8`。這些是限幅的初始設定，仍需實車檢查。若Encoder每輪脈衝143／147不是按目前A相RISING實際量測，RPM及同步效果會不準。終端STATUS顯示TURN、PWM_L/R、RPM_L/R、TRIM，便於確認。

## 短暫失線

確認可靠双線並開始行駛後，單邊線缺失時使用最近記住的車道寬度推算中心、低速回線，畫橘色虛線。完全失線時沿用最後方向，不盲目左右掃描。單邊推算與記憶不能刷新可靠雙線計時，最長0.6秒。

重新看到3個不同時間的可靠雙線影格才確認找回，重新從低速加速。相機讀取失敗、影像年齡超過0.3秒、配對模糊或推算偏移過大立即停止。ESP32通訊逾時0.5秒亦停止，重啟ESP32需要重新握手，回MANUAL STOP後重新選AUTO。

此功能是前方局部近似直線的置中與短暫回線，無法保證完全看不到線時仍能判斷新的急彎或岔路，尚未加入障礙物偵測或整條賽道地圖。

## 驗證

在Windows／Python3.12／OpenCV4.10完成控制、影像與恢復行為離線測試，另檢查Python3.6語法。ESP32以esp32核心3.3.11與DOIT ESP32 DEVKIT V1編譯。尚未在你的Nano與實車量測，因此需以畫面FPS/PROC/AGE與實際RPM確認延遲、轉向效果和馬達負載。

根目錄執行 `python3 -m unittest -v lane_centering_v6.test_centering` 可重現新控制器15項測試；另保留原影像及回線測試，整體檢查共28項。
